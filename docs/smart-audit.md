# Smart Audit translation intelligence

Smart Audit uses the existing document TM, approved glossary and persisted translation sessions. It reconstructs DrawingML paragraphs with the same IDs and text decoder as the PPTX translator. It analyzes text without changing the uploaded file or reading presentation images.

The audit recognizes capitalization, punctuation, Unicode composition, missing/wrong Vietnamese accents and joined words. Exact/compact indexes resolve repeated text locally; an inverted index limits fuzzy candidates. Numbers, negation, sequence and direction differences block reuse. The audit tolerances live in `services/translation/audit-intelligence.ts`; they deliberately do not change the translator's strict canonical keys. Confidence values rank evidence rather than representing calibrated probabilities.

Translation relationships come from known glossary/TM mappings, unique complementary paragraphs in the same container, or recognizable bilingual segments inside a paragraph. A crowded container is not automatically marked translated. Current-deck observations remain `ESTABLISHED` in document TM. Historical AI results require review, while edits saved through the existing download flow carry a `userCorrected` marker. Session language direction is retained through save/export, including expired-session fallback. No vector database, NLP service or additional AI requests are introduced by scanning.

Review groups separate translation gaps, conflicting translations and Vietnamese variants. Conflicts show usage counts and approved terminology before dominant usage. A suggestion includes confidence, reasons and its source. Users can ignore a group for the current scan, review individual positions, or preview a batch with its complete position count before applying it. Safe corrections are offered separately; accent, spelling and semantic changes require review.

For VI → EN repair, English content already in the file is preserved and excluded from suggestion and consistency groups. Differences such as `Cutting die` versus `cutting die`, alternate English wording in history, and glossary preferences do not request editing those paragraphs again. Source text with Vietnamese evidence, including known accentless phrases and mixed-language leftovers, remains eligible for translation. EN → VI audits retain their existing source-language behavior.

This rule is conservative: text without Vietnamese evidence cannot receive an English repair suggestion even when footwear vocabulary confuses the older language heuristic (for example `May 2026`, `Lot number`, or `day shift`). Server re-scanning rejects stale attempts to apply English corrections. Opening Smart Audit performs a fresh scan and clears its previous report, rather than reopening cached suggestions.

VI → EN suggestions are checked against the current approved glossary before ranking or displaying them, including historical AI translations and saved corrections. Audit and translation share the safety filter for corrupted glossary rows. Known synonyms are repaired only when their corresponding source term matches (for example `Cộm → X-ray` repairs `lumpy`, `lumps` and `lumpiness`). Unresolved candidates are withheld and remain selected for fresh translation; they cannot be directly applied. Reused historical text still requires contextual review even when it passes terminology validation. The evidence score is not a guarantee of translation quality.

Incremental repair applies document memory before glossary enforcement. It validates each selected new translation, retries paragraphs with missing glossary terms once with explicit constraints, and refuses delivery if the corrective pass still fails. Existing English counterparts remain protected. Scanning itself makes no AI calls. The regression suite includes the reported sentence, direct apply, bad historical candidates, scope-limited synonym replacement, corrective retry and failed-delivery handling.

The `apply_audit` API re-scans and verifies both the selected IDs and the previewed source/replacement text. It changes only the selected paragraph text nodes, preserving surrounding XML and every other ZIP part. Length-changing edits require uniform run styles; fields, explicit line breaks and mixed formatting require manual editing. Accent-only changes can retain different run styles and the original boundaries. Notes and SmartArt text are reported for review and are not automatically modified. Other embedded text parts that the existing translator does not support remain outside automated fixes.

The primary Smart Audit action, `Dịch & sửa phần chưa dịch`, uses exact paragraph IDs. Unresolved source paragraphs remain selectable even if historical suggestions conflict or an approved mapping exists. Approved mappings can resolve locally; conflicts bypass cached AI results. `untranslatedCount` counts missing text in the file independently of memory status, while `translatableMissingCount` counts positions with supported structure. The action downloads the already packaged incremental result through the session GET endpoint, replaces the current in-memory upload and scans it again. It never routes that result through the full-deck export/rebuild path. The translator also returns a refreshed audit of its output.

ISQ slides in bilingual modes are selected as a whole slide and become an English slide followed immediately by a Vietnamese reference slide. Partial ISQ selections fail before AI requests. Existing EN/VI paragraphs in one box are separated between these slides; their English counterpart can be reused without retranslating. Direct suggestion replacement is disabled for source paragraphs that need this ISQ structure change. The source slide is cloned before translation, including its relationship file. Pair roles are recorded in the PPTX custom XML so the next audit skips VI references and does not duplicate existing pairs. Both crawler and scanner follow the actual presentation relationship order, including newly interleaved slides. Explicit `replace_en` still means English only.

Mixed fonts and proofing metadata do not prevent translation. A translation with differing run styles uses the dominant substantive source style, retaining paragraph properties and source font/size/color; partially bold text does not become fully bold. Explicit translation line breaks are rendered as DrawingML breaks. Fields and read-only notes/SmartArt remain manual work. Conservative direct spelling/reuse edits still require uniform visual formatting or same-length accent correction. Unselected ordinary slides and paragraphs are preserved. English ISQ copies are checked for Vietnamese before packaging, while VI reference copies are excluded from missing-translation counts. The ordinary full-translation workflow remains in place.

Run focused regression checks with:

```powershell
node node_modules/tsx/dist/cli.mjs --test tests/smart_audit_intelligence.test.mjs tests/smart_audit_memory.test.mjs tests/smart_detector.test.mjs tests/document_tm.test.mjs
node node_modules/typescript/bin/tsc --noEmit
npm.cmd run build
```

The new tests use synthetic text-only PPTX fixtures. They cover matching variants, identifiers, mixed language, conflicts, trust priority, persistent correction provenance, exact selection, bilingual output, XML integrity and repeated large-deck content. Unknown names, unanchored single words, uncertain relationships and fuzzy semantic candidates remain review items. This local evidence layer is intentionally not a general Vietnamese grammar checker.
